# 10 跨项目协同：Paw Trip（你）× Paw Track/Care（老婆）

> 目标：两个产品**各自独立发布**，但共用账号、狗狗档案和设计系统，不互相踩脚。现在我只知道 Trip 的情况，Track 的状态需要和老婆确认。

## 要先对齐的事（一个共用的“约定”）

| 主题 | 要对齐什么 | 建议默认 |
|---|---|---|
| **后端** | 是否共用同一个 Supabase 项目 | 共用 `paw-backend`，各自用独立的数据库分区（`care`） |
| **账号** | 登录方式、用户表 | 共用 `auth.users` 与 `public.profiles` |
| **狗狗档案** | 表结构（名字、生日、品种、体重、芯片、过敏、常去兽医） | 以 Trip 现有 `public.dogs` 为基础，扩展（L02） |
| **权限** | 谁能看谁的狗狗数据 | 默认只有主人；分享要明确授权（临时链接/家庭成员） |
| **设计系统** | 字体、颜色、图标、组件 | 共用同一套（见 `docs/icon-style-brief.md`、主题文件） |
| **技术栈** | 是否同样是 Expo/React Native | 建议一致，才能共用代码 |
| **仓库** | 前端怎么放 | 做第二个 App 时合并为 monorepo（`apps/trip`、`apps/care`、`packages/ui`、`packages/core`） |
| **命名** | “Paw Track”与“Paw Trip”太像 | 建议考虑 Paw Care / Paw Health / Paw Log |
| **域名** | 子域名分配 | `care.根域名`（或 `track.`） |
| **发布** | 各自的 Bundle ID、Apple 账号 | 同一个开发者账号，不同 Bundle ID（`app.根域名反写.care`） |
| **数据迁移** | 以后如何互相读取 | 通过共用表与深度链接，不互相调用对方的 App |

## 问老婆的问题（请她回答，然后我来整理）

1. Track 现在做到哪了？用的技术栈？代码仓库和后端（Supabase？）在哪？
2. 已有的数据表有哪些（尤其狗狗、体重、疫苗）？
3. 第一版想做哪些功能？目标用户是谁？
4. 已经有真实用户或测试者了吗？
5. 她打算什么时候上线、上 iOS 还是只做网页？
6. 她用的名字、logo 是什么？愿意统一到 “Paw ___” 系列吗？
7. 她对共用账号、狗狗档案是否有顾虑？

## 对 Trip 现有结构的意见（供共用时参考）

- **狗狗属于用户**（`dogs.owner_id`），不依赖行程——这是对的，Care 可以直接复用。
- **账号资料**（`profiles`：名字、唯一 ID、头像、兴趣）已经是共用的。
- **要扩展的**：狗狗的出生日期、品种、芯片号、过敏、常用兽医；体重历史、疫苗、看诊放进 `care` 分区。
- **隐私**：体重、诊疗是私人数据，不应被行程成员默认看到；Trip 里只展示“这只狗的基本信息 + 性格”。

## 同步节奏

- **每两周**一次 30 分钟同步：进度、阻塞、共用约定有没有变化。
- 共用表结构变化，必须先在 `09-risks-decisions.md` 记录决定，再改迁移。
- 发布前互相检查：是否影响对方（共用表、共用登录、共用图片存储）。
